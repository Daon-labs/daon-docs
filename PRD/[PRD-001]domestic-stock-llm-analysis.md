# 국내주식 LLM 분석 제품 요구사항

- 작성일: 2026-05-11
- 문서 상태: 초안
- 범위: 국내주식 전용
- 관련 후속 문서: 기술 요구사항, 초기 아키텍처, 데이터/캐싱/DB 설계, 카카오톡 1:1 Agent 설계

## 1. 제품 목적

Daon은 사용자가 국내주식 종목에 대해 자연어로 질문하면, 실시간 흐름과 과거 흐름을 함께 이해해 근거 있는 답변을 제공하는 주식 분석 대화형 Agent 제품이다.

사용자는 차트, 호가, 체결, 분봉, 일봉, 투자자 동향, 뉴스/공시성 이벤트를 직접 오가며 원인을 추정하지 않고, 다음과 같은 질문을 바로 던질 수 있어야 한다.

- "지금 이거 왜 떨어지는 거야?"
- "4시간 전에 왜 떨어진 거야?"
- "오늘 장중에서 지금까지 특별한 일 없었어?"
- "요즘 장기적 추세 정리해줘."
- "A, B, C, D 주식 중 어떤 주식이 매력적인지 분석해줘."

핵심 가치는 단순한 현재가 조회가 아니라, 가격 움직임의 맥락을 설명하고 사용자가 다음 판단을 할 수 있도록 돕는 것이다.

## 2. 핵심 기능

### 2.1 LLM 기반 국내주식 흐름 질의/분석

사용자는 특정 국내주식 종목 또는 여러 종목에 대해 자연어로 질문한다. 시스템은 질문 의도를 파악하고, 해당 질문에 필요한 시장 흐름과 종목 데이터를 바탕으로 분석 답변을 제공한다.

이 기능은 다음 질문 유형을 우선 지원한다.

| 질문 유형 | 사용자 의도 | 기대 답변 |
| --- | --- | --- |
| 현재 급락/급등 원인 | 지금 발생한 가격 움직임의 이유 파악 | 현재가 변화, 체결 흐름, 거래량, 호가 변화, 시장/업종 흐름, 확인 가능한 이벤트를 구분해 설명 |
| 특정 시점 변동 원인 | 과거 장중 특정 시점의 움직임 복기 | 해당 시점 전후의 가격/거래량/체결 변화와 가능한 원인을 시간순으로 설명 |
| 오늘 장중 특이사항 | 당일 흐름 전체의 핵심 이벤트 파악 | 시초가 이후 주요 변곡점, 거래량 급증 구간, 낙폭/상승폭 확대 구간, 관련 이벤트 요약 |
| 장기 추세 요약 | 최근 며칠~수개월 흐름 파악 | 추세 방향, 변동성, 지지/저항 성격의 가격대, 거래량 변화, 수급/실적/이슈 맥락 요약 |
| 복수 종목 비교 | 후보 종목 중 상대 매력도 판단 | 가격 흐름, 추세, 변동성, 거래대금, 재무/전망/수급 등 비교 기준별 장단점과 최종 판단 |

답변은 가능한 한 "무슨 일이 있었는지", "그것이 왜 중요해 보이는지", "확실한 근거와 추정이 무엇인지"를 분리해서 제공해야 한다.

### 2.2 카카오톡 1:1 대화형 Agent 제공

Daon의 분석 기능은 웹사이트 내 채팅 UI에만 묶이지 않아야 한다. 사용자는 카카오톡 1:1 채팅방에서 Daon 봇과 대화하며 동일한 국내주식 분석 기능을 사용할 수 있어야 한다.

## 3. 사용자와 사용 시나리오

### 3.1 주요 사용자

- 국내주식을 직접 매매하거나 관찰하는 개인 투자자
- 여러 관심 종목을 추적하며 장중 변동 이유를 빠르게 파악하고 싶은 사용자
- 종목별 흐름을 매번 수동으로 정리하기보다, 대화형으로 핵심만 확인하고 싶은 사용자
- 카카오톡 1:1 대화에서 종목 흐름을 빠르게 묻고 답을 받고 싶은 사용자

### 3.2 대표 시나리오

#### 시나리오 A. 현재 급락 원인 확인

사용자가 "삼성전자 지금 왜 떨어지는 거야?"라고 질문한다.

제품은 현재 시점의 가격 하락폭, 거래량 변화, 장중 주요 변곡점, 시장/업종 동반 하락 여부, 확인 가능한 뉴스/공시성 이벤트를 함께 검토한다. 답변은 단정하지 않고, 데이터로 확인되는 사실과 가능한 해석을 분리한다.

#### 시나리오 B. 특정 시점의 장중 변동 복기

사용자가 "4시간 전에 왜 갑자기 빠졌어?"라고 질문한다.

제품은 질문 시점 기준 약 4시간 전 구간을 찾고, 해당 전후의 분봉/체결/거래량 변화와 당일 전체 흐름 속 의미를 설명한다. 특정 원인을 확인할 수 없으면 "데이터상 관찰되는 변화"와 "확인되지 않은 원인"을 구분한다.

#### 시나리오 C. 오늘 장중 특이사항 요약

사용자가 "오늘 장중 지금까지 특별한 일 없었어?"라고 질문한다.

제품은 장 시작 이후 현재까지의 주요 변곡점, 거래량 급증 구간, 고점/저점 형성 구간, 시장 대비 상대 강약을 요약한다. 사용자가 빠르게 판단할 수 있도록 시간순 요약과 핵심 결론을 함께 제공한다.

#### 시나리오 D. 장기 추세 정리

사용자가 "요즘 장기적 추세 정리해줘"라고 질문한다.

제품은 최근 일/주/월 단위 흐름을 종합해 추세 방향, 변동성, 거래량, 최근 주요 가격대, 수급 또는 재무/전망성 맥락을 설명한다. 단기 노이즈와 장기 추세를 구분해야 한다.

#### 시나리오 E. 복수 종목 비교

사용자가 "A, B, C, D 중 어떤 주식이 매력적이야?"라고 질문한다.

제품은 비교 기준을 명시하고 각 종목의 장단점을 정리한다. 비교는 가격 모멘텀만으로 끝나지 않고, 거래대금/변동성/추세 안정성/수급/기초 지표 등 확인 가능한 범위에서 균형 있게 수행한다.

## 4. 제품 요구사항

### 4.1 대화 경험

- 사용자는 종목명, 종목코드, 별칭에 가까운 표현으로 질문할 수 있어야 한다.
- 질문이 모호하면 제품은 임의로 단정하지 않고 필요한 확인 질문을 해야 한다.
- 답변은 한국어를 기본으로 한다.
- 답변은 긴 리포트보다 먼저 핵심 결론을 제시하고, 이후 근거를 구조화해 보여준다.
- 사용자는 후속 질문에서 "그때", "아까 말한 구간", "다른 종목이랑 비교해줘"처럼 이전 대화 맥락을 참조할 수 있어야 한다.

### 4.2 답변 품질

- 답변은 확인된 데이터와 추정을 명확히 구분해야 한다.
- 가격 변동의 원인을 단일 이유로 과도하게 단정하지 않아야 한다.
- 데이터가 부족하거나 원인이 확인되지 않으면 그 사실을 명시해야 한다.
- 투자 조언처럼 보일 수 있는 표현은 신중하게 다루고, 판단 근거와 리스크를 함께 제공해야 한다.
- 복수 종목 비교에서는 최종 추천 또는 우선순위를 제시하되, 비교 기준과 불확실성을 함께 밝혀야 한다.

### 4.3 데이터 신선도에 대한 제품 기대

- "지금", "현재", "방금" 같은 질문은 가능한 최신 장중 데이터를 기준으로 답변해야 한다.
- "4시간 전", "오늘 장중" 같은 질문은 해당 시점 또는 당일 구간 데이터를 기준으로 답변해야 한다.
- "요즘", "장기적" 같은 질문은 일봉/주봉/월봉 성격의 장기 흐름을 반영해야 한다.
- 답변에는 분석 기준 시각 또는 데이터 기준 시각을 표시해야 한다.
- 데이터가 지연되었거나 일부 데이터가 아직 반영되지 않았을 가능성이 있으면 사용자에게 알려야 한다.

### 4.4 국내주식 범위

- 1차 제품 범위는 국내주식으로 제한한다.
- 해외주식, 해외선물옵션, 국내선물옵션, 채권, ELW 등은 이번 제품 요구사항 범위에서 제외한다.
- KIS Open API 관련 판단은 프로젝트의 KIS Open API 전체 문서를 우선 기준으로 삼는다.
- 실전 API 기준으로 기획하며, 모의투자 API 또는 모의 fallback은 제품 요구사항에 포함하지 않는다.

### 4.5 카카오톡 1:1 Agent 사용 경험

- 사용자는 카카오톡 1:1 채팅방에서 웹 UI와 동일한 분석 질문을 할 수 있어야 한다.
- Agent 응답은 카카오톡에서 빠르게 읽을 수 있는 자연어 답변을 우선하되, 내부적으로는 근거 데이터와 분석 요약을 구조화해 보존할 수 있어야 한다.
- 사용자는 카카오톡에서 여러 종목을 반복 조회하거나 비교할 수 있어야 한다.
- 사용자는 웹 UI 없이도 카카오톡 1:1 대화를 통해 Daon의 핵심 분석 기능을 사용할 수 있어야 한다.
- Agent는 사용자의 최근 대화 맥락을 활용해 "그 종목", "아까 말한 구간", "다른 종목이랑 비교" 같은 후속 질문을 처리할 수 있어야 한다.

## 5. MVP 범위

### 5.1 MVP에 포함

- 국내주식 단일 종목 현재 흐름 분석
- 국내주식 단일 종목 당일 장중 특이사항 요약
- 국내주식 단일 종목 특정 장중 시점 변동 설명
- 국내주식 단일 종목 최근 장기 추세 요약
- 국내주식 복수 종목 비교 분석
- 웹 UI 또는 내부 클라이언트에서 대화형 분석 검증
- 카카오톡 1:1 Agent를 통한 동일 분석 기능의 기본 제공
- tracing 종목 관리하는 관리자 기능 제공

### 5.2 MVP에서 제외

- 자동 매매 또는 주문 실행
- 포트폴리오 운용 자동화
- 해외주식 분석
- 모의투자 API 기반 기능
- 사용자의 계좌 잔고, 주문, 체결 내역 기반 개인화 분석
- 정교한 투자 자문, 목표가 제시, 매수/매도 신호 자동 생성
- 뉴스 원문 전문 저장 또는 유료 데이터 재배포
- 외부 MCP 서버 제공

## 6. 목표 서비스 규모

MVP는 실제 대규모 상용 서비스 이전 단계이지만, 장중 트래픽 집중, 관심 종목 쏠림, 외부 API 호출 제한, 데이터 신선도 저하, LLM 응답 지연 같은 문제를 경험하고 해결 과정을 기록할 수 있는 규모를 목표로 한다.

### 6.1 MVP 규모 가정

- 가입 사용자: 1,000명
- 월간 활성 사용자(MAU): 300명
- 일간 활성 사용자(DAU): 50~100명
- 장중 피크 동시 활성 사용자: 10~30명
- 사용자당 일 분석 질문 수: 10~50개
- 일 분석 질문 수: 500~3,000개
- 사용자가 등록하거나 반복 조회하는 관심 종목 수: 500~2,000개
- 장중 특정 인기 종목에 대한 질문 집중을 허용한다.

이 수치는 제품과 백엔드 설계의 목표 부하를 정의하기 위한 가정이다. KIS API의 정확한 TPS, WebSocket 구독 한도, 캐싱 TTL, 큐잉 정책, 장애 시 degrade 방식은 후속 기술 요구사항 문서에서 별도로 산정한다.

### 6.2 운영 목표

제품 개발 과정에서는 기능 구현뿐 아니라 문제 상황을 예측하고 해결한 과정을 기록한다. 특히 다음 항목은 설계/개발/운영 로그에 남길 수 있어야 한다.

- 실시간 데이터와 REST 조회 데이터의 불일치 처리
- KIS API 호출 제한으로 인한 요청 지연 또는 데이터 갱신 지연
- 인기 종목 쏠림으로 인한 캐시 효율과 큐 대기 문제
- LLM 컨텍스트가 길어질 때의 비용, 지연, 품질 저하
- 동일 질문 반복 요청에 대한 캐싱과 재사용 전략
- 장중 피크 시간대 응답 지연과 사용자 안내 방식
- 데이터 부족, 외부 API 오류, LLM 오류 발생 시 사용자에게 제공할 fallback 응답
- 카카오톡 1:1 Agent와 웹 UI에서 동일 분석 품질을 유지하는 문제

## 7. 성공 기준

MVP는 다음 기준을 만족해야 한다.

- 사용자가 대표 질문 5종을 자연어로 입력했을 때 의도를 올바르게 분류한다.
- 단일 종목 현재 흐름 질문에 대해 최신 데이터 기준 시각과 함께 설명한다.
- 특정 시점 질문에 대해 해당 구간을 찾아 시간순으로 설명한다.
- 오늘 장중 요약에서 주요 변곡점과 거래량 변화 구간을 빠뜨리지 않는다.
- 장기 추세 요약에서 단기 움직임과 장기 흐름을 구분한다.
- 복수 종목 비교에서 비교 기준과 최종 판단을 함께 제시한다.
- 확인되지 않은 원인을 단정하지 않고 불확실성을 명시한다.
- 카카오톡 1:1 Agent에서도 핵심 분석 질문을 수행할 수 있다.
- 목표 서비스 규모의 장중 사용 패턴을 가정한 부하 시나리오를 정의하고 검증할 수 있다.
- 주요 문제 상황과 해결 과정을 기술 문서 또는 개발 로그로 남길 수 있다.

# KIS API 데이터 수집 전략 제품 요구사항

- 작성일: 2026-05-12
- 문서 상태: 초안
- 범위: 국내주식 분석용 KIS Open API 데이터 전략
- 관련 문서: `[PRD-001]domestic-stock-llm-analysis.md`
- 기준 문서: `데이터/한국투자증권_오픈API_전체문서_20260504_030007.xlsx`

## 1. 목적

이 문서는 Daon이 국내주식 LLM 분석 제품 목표를 달성하기 위해 KIS Open API에서 어떤 데이터를 수집해야 하는지, 각 API가 어떤 분석 가치에 기여하는지, API별 데이터 신선도와 호출 주기를 어떻게 설계할지 정의한다.

PRD 001의 핵심 가치는 단순 현재가 조회가 아니라 "가격 움직임의 맥락을 설명하는 것"이다. 따라서 데이터 수집은 다음 질문에 답할 수 있어야 한다.

- 지금 왜 급등하거나 급락하는가?
- 특정 시점에 왜 움직였는가?
- 오늘 장중에 어떤 변곡점과 이벤트가 있었는가?
- 최근 며칠에서 수개월 동안의 추세는 어떤가?
- 여러 종목 중 어떤 종목이 상대적으로 매력적인가?

## 2. 범위와 원칙

### 2.1 포함 범위

- 국내주식 현재가, 체결, 호가, 예상체결, 분봉, 일/주/월/년봉
- 국내 업종/시장 지수와 업종 분봉/일자별 흐름
- 투자자 매매동향, 외국인/기관 가집계, 프로그램매매
- 종합 시황/공시 제목, VI 현황, 장운영/휴장 정보
- 종목 기본정보, 재무제표, 재무비율, 추정실적, 투자의견
- 순위 분석 API를 활용한 이상 종목/시장 이벤트 탐지
- 배당, 증자, 합병/분할, 주주총회 등 예탁원 일정성 이벤트

### 2.2 제외 범위

- 주문, 정정/취소, 잔고, 계좌, 매수 가능 금액 등 매매/계좌 API
- 모의투자 API와 모의 fallback
- 해외주식, 해외선물옵션, 국내선물옵션, 채권, ELW 중심 기능
- 자동 매매, 투자 자문, 목표가/매수/매도 신호 자동 생성

단, ETF/ETN은 국내시장 비교나 확장 기능에서 유용하므로 P2 확장 후보로만 둔다.

### 2.3 데이터 주기 해석 원칙

KIS 엑셀 문서는 API별 공식 데이터 갱신 주기를 일괄적으로 명시하지 않는다. 따라서 이 문서의 "권장 갱신 주기"는 API 통신 방식, 데이터 성격, 장중 분석 필요도, 외부 API 호출 제한 리스크를 기준으로 한 제품 설계 기준이다.

- WebSocket API는 장중 구독 기반 이벤트 수신을 우선한다.
- REST API는 질문 시점 조회, 캐시 보강, 재연산, WebSocket 누락 보정에 사용한다.
- 장중 데이터는 "수집 주기"와 "LLM 답변에 허용할 최대 지연"을 분리한다.
- 모든 답변에는 데이터 기준 시각을 표시해야 한다.
- API 호출 제한이 확인되면 후속 기술 문서에서 종목 우선순위, 큐잉, TTL을 조정한다.

## 9. 단계별 도입 계획

### 9.1 1단계: MVP 필수 데이터

- 인증: 접근토큰발급, 웹소켓 접속키 발급
- 실시간: 통합 실시간체결가, 통합 실시간호가, 장운영정보
- REST 보강: 현재가 시세, 호가/예상체결, 현재가 체결
- 과거/복기: 당일분봉, 일별분봉, 기간별시세
- 시장 맥락: 업종 현재지수, 업종 분봉, 업종 일자별지수
- 이벤트: VI 현황, 종합 시황/공시 제목, 휴장일

이 단계만으로 PRD 001의 단일 종목 현재 흐름, 특정 시점 복기, 오늘 장중 특이사항, 장기 추세 요약의 기본 품질을 달성해야 한다.

### 9.2 2단계: 분석 신뢰도 강화

- 투자자/수급: 주식현재가 투자자, 종목별 투자자매매동향, 시장별 투자자매매동향, 외인기관 가집계
- 프로그램매매: 종목별/시장별 프로그램매매 당일 및 일별
- 재무: 주식기본조회, 재무비율, 손익계산서, 대차대조표, 안정성비율
- 의견/추정: 종목투자의견, 종목추정실적

이 단계는 복수 종목 비교와 장기 추세 답변의 품질을 높인다.

### 9.3 3단계: 선제 탐지와 운영 고도화

- 순위 API: 거래량, 등락률, 체결강도, 대량체결, 호가잔량, 조회상위, 신고/신저, 공매도/신용잔고 상위
- 시간외/예상체결 순위: 장전/장마감/시간외 변동 후보 탐지
- 예탁원 일정: 배당, 증자, 합병/분할, 주주총회, 상장 일정
- 관리자 조건검색: 조건검색 목록/결과 조회

이 단계는 사용자가 묻기 전에 이상 흐름 후보를 준비하고, 카카오톡 Agent의 응답 속도와 선제 알림성 기능을 강화한다.

### 9.4 4단계: ETF/ETN과 보조 시장 데이터

- ETF/ETN 현재가, NAV 비교추이, ETF 구성종목시세
- 금리 종합, 국내 증시자금 종합

이 단계는 국내주식 분석의 거시/섹터 보조 맥락을 넓힌다. 단, PRD 001의 국내주식 MVP보다 우선하지 않는다.

## 11. 답변 생성 시 데이터 사용 규칙

- 실시간 데이터, REST 스냅샷, 일별 확정 데이터를 서로 다른 데이터 등급으로 취급한다.
- 추정 수급과 확정 수급은 답변에서 분리한다.
- 뉴스/공시 제목은 원인 확정 근거가 아니라 이벤트 후보로 표현한다.
- 종목의 급변 원인은 가격/체결/호가/시장/업종/수급/이벤트 중 확인된 항목과 추정 항목을 분리한다.
- 장중 일봉, 장중 수급, 예상체결 데이터는 미확정 데이터임을 표시한다.
- API 응답이 지연되거나 캐시가 오래된 경우 답변에 데이터 기준 시각과 제한을 표시한다.

## 12. 성공 기준

- P0 API만으로 PRD 001의 대표 질문 5종 중 단일 종목 현재 흐름, 특정 시점 복기, 오늘 장중 특이사항, 장기 추세 요약을 생성할 수 있다.
- 각 답변은 사용한 데이터 기준 시각과 최신성 상태를 포함한다.
- 현재 급등/급락 답변은 체결, 호가, 거래량, 시장/업종, VI/뉴스 후보를 분리해 설명한다.
- 특정 시점 복기는 해당 구간 전후의 분봉/체결 변화를 시간순으로 제시한다.
- 복수 종목 비교는 최소 가격 모멘텀, 거래대금/유동성, 변동성, 수급, 재무 중 사용 가능한 기준을 명시한다.
- API 호출 제한이나 장애가 발생해도 캐시 데이터 기준 시각과 제한 사항을 사용자에게 안내한다.

## 13. 후속 문서화 범위

이 문서는 어떤 데이터를 왜 수집할지 정의한다. 다음 항목은 후속 기술 문서에서 다룬다.

- KIS API 호출 제한 확인과 TPS 예산
- WebSocket 구독 종목 수 제한과 재구독 전략
- Redis/DB 캐시 TTL과 스키마
- tick, 1초봉, 1분봉, 일봉 저장 정책
- 장중 인기 종목 우선순위 큐
- LLM tool 입출력 스키마
- 데이터 누락/지연/불일치 감지와 fallback
- 카카오톡 Agent 응답 길이와 데이터 출처 표시 방식

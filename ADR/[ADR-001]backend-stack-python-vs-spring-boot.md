## 배경

Daon MVP는 국내주식 사용자가 자연어로 질문하면 실시간 흐름, 장중/장기 시세, 투자자 동향, 재무/전망성 데이터, LLM 분석을 조합해 답변해야 한다.

PRD 기준 MVP에는 웹 또는 내부 클라이언트뿐 아니라 카카오톡 1:1 Agent, tracing 종목 관리 관리자 기능, 장중 피크 부하 시나리오 검증, 장애/지연 상황 기록이 포함된다.

KIS Open API 문서 기준으로 국내주식 분석에는 실전 REST API와 WebSocket API가 함께 필요하다. 예를 들어 현재가는 `FHKST01010100`, 당일 분봉은 `FHKST03010200`, 기간별 시세는 `FHKST03010100`, 실시간 체결/호가는 `H0UNCNT0`, `H0UNASP0`, `H0STCNT0`, `H0STASP0` 계열을 사용한다. 기획과 구현은 모의투자 API나 모의 fallback이 아니라 실전 API 기준으로 한다.

## 결정

주 백엔드 스택은 Java 21 + Spring Boot 3.x로 결정한다.

Python은 주 운영 백엔드가 아니라 분석 실험, 데이터 검증, 향후 분리형 분석 worker 후보로 제한한다. 사용자 요청 처리, KIS 토큰과 호출 제한 관리, 실시간 수집, 카카오톡 Webhook, 세션/대화 맥락, 관리자 기능, 관측성은 Spring Boot 백엔드가 소유한다.

## 대안

| 대안 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| Python + FastAPI | LLM/데이터 분석 생태계가 강하다. 초기 프로토타이핑이 빠르다. 비동기 HTTP/WebSocket 구현이 가능하다. | 장중 실시간 수집, 외부 API 호출 제한, 장기 운영, 트랜잭션/관리자 기능, 팀 단위 구조화에서 규율을 별도로 강하게 설계해야 한다. 운영 백엔드와 분석 실험 코드의 경계가 흐려질 위험이 있다. | 주 백엔드로는 보류한다. |
| Java 21 + Spring Boot 3.x | 운영 백엔드, REST API, Webhook, DB 트랜잭션, 스케줄링, 관측성, 테스트 구조를 안정적으로 가져가기 쉽다. KIS REST/WebSocket adapter, 캐시, 큐, 관리자 기능을 한 애플리케이션 안에서 명확히 분리할 수 있다. | LLM/데이터 분석 실험 속도는 Python보다 느릴 수 있다. 일부 지표 계산이나 탐색적 분석은 코드가 장황해질 수 있다. | 주 백엔드로 채택한다. |
| 혼합형: Spring Boot API + Python 분석 서비스 | 운영 경계와 분석 생태계를 모두 살릴 수 있다. 분석 로직을 독립적으로 확장할 수 있다. | MVP 초기부터 서비스 간 통신, 배포, 장애 전파, 데이터 계약 관리가 늘어난다. 현재 목표 규모에서는 복잡도가 먼저 커진다. | MVP 초기에는 채택하지 않고, 재검토 조건 충족 시 분리한다. |

## 근거

- PRD의 핵심 리스크는 단순 LLM 호출보다 실시간/REST 시장 데이터 조합, KIS 호출 제한 대응, 캐시/큐, 사용자 응답 지연, 카카오톡 Webhook, 운영 로그에 있다.
- MVP 목표 규모는 DAU 50~100명, 장중 피크 동시 활성 사용자 10~30명으로 작지만, 인기 종목 쏠림과 데이터 신선도 문제가 제품 품질을 좌우한다.
- KIS API는 REST와 WebSocket을 함께 사용해야 하며, 토큰/접속키/구독/재시도/TTL을 중앙에서 통제해야 한다.
- Spring Boot는 API, DB, 캐시, 스케줄링, 관측성, 관리자 기능을 하나의 운영 백엔드로 구성하기에 적합하다.
- Python의 강점은 유지하되, 운영 요청 경로에 바로 섞지 않아야 장애 원인과 책임 경계가 명확하다.

## 영향

- 좋아지는 점:
  - 운영 백엔드의 책임 경계가 명확해진다.
  - KIS adapter, 분석 orchestration, Kakao adapter, 관리자 기능을 같은 타입/테스트 체계로 관리할 수 있다.
  - 실전 API 기준의 rate limit, 캐시, 재시도, 장애 응답 정책을 중앙화하기 쉽다.
- 감수할 점:
  - LLM 프롬프트 실험과 데이터 분석 반복 속도는 Python 단일 스택보다 느릴 수 있다.
  - Python 기반 분석 라이브러리가 필요해지는 시점에는 별도 worker 또는 batch 도구 설계가 필요하다.
- 후속 작업:
  - Spring Boot 초기 프로젝트 구조를 정의한다.
  - KIS REST/WebSocket adapter 인터페이스와 TTL 정책을 설계한다.
  - PostgreSQL/Redis 스키마와 캐시 키 정책을 문서화한다.
  - Python 분석 도구를 운영 요청 경로와 분리하는 기준을 정한다.

## 재검토 조건

- 분석 정확도에 Python 전용 라이브러리가 필수이며 Java 구현 비용이 제품 속도를 크게 막는다고 확인된 경우
- LLM/분석 작업의 CPU 또는 I/O 부하가 API 서버 안정성을 저해해 별도 worker 분리가 필요한 경우
- KIS 수집 worker와 사용자 API 서버의 배포/스케일링 주기가 명확히 달라진 경우
- 팀의 주 개발 역량 또는 운영 담당 역량이 Python 중심으로 바뀐 경우
